# غرف الويب برمز

يعمل مسار الويب عبر بروتوكول WebSocket الموجود في `server/multiplayer`، لذلك لا يستخدم mDNS أو TCP المباشر. ينشئ المضيف غرفة خاصة برمز، ويدخل الضيف الرمز نفسه من المتصفح.

## عنوان خادم الغرف

عند نشر الويب والخادم خلف النطاق نفسه، يستخدم العميل تلقائياً المسار التالي:

```text
wss://YOUR_DOMAIN/multiplayer
```

عند استضافة خادم الغرف على نطاق مستقل، اضبط متغير البناء التالي قبل تصدير نسخة الويب:

```text
EXPO_PUBLIC_MP_SERVER_URL=wss://YOUR_WEBSOCKET_DOMAIN/multiplayer
```

لا تضع عنوان `ws://` غير مشفر داخل صفحة منشورة عبر `https://`؛ المتصفح سيمنع الاتصال المختلط. استخدم `wss://` في الإنتاج.

## تشغيل الخادم

يبدأ خادم الغرف المحلي أثناء التطوير بالأمر التالي:

```bash
pnpm server:multiplayer
```

تكون نقطة الصحة متاحة على `/health`، وWebSocket على `/multiplayer`. في النشر الدائم يجب تشغيل هذه العملية باستمرار خلف HTTPS/WSS؛ الغرف محفوظة في الذاكرة لذلك يلزم مثيل خادم واحد للمباريات النشطة.

## أسرع نشر سحابي: Render

يوجد ملف `render.yaml` في جذر المستودع لإعداد خدمة خادم الغرف. بعد تسجيل الدخول إلى [Render](https://render.com/)، اختر **New → Blueprint**، واربط مستودع GitHub `ayf09/CardClash` ثم وافق على ملف الإعداد. يبدأ الملف بخطة تجريبية مجانية؛ سيبني Render خادم الغرف بالأمر `pnpm build:multiplayer` ويشغله بالأمر `pnpm start:multiplayer`، ويراقب `/health`. قبل اعتماد اللعب العام الدائم، غيّر الخطة إلى خدمة تبقى نشطة ولا تنام من لوحة Render، ثم راجع تسعيرها الحالي مباشرة في حسابك.

بعد النشر انسخ رابط الخدمة، مثال: `https://card-clash-rooms.onrender.com`، ثم اضبط متغير بناء الويب الآتي قبل نشر واجهة Expo Web:

```text
EXPO_PUBLIC_MP_SERVER_URL=wss://card-clash-rooms.onrender.com/multiplayer
```

استخدم رابط `wss://` فقط في الموقع المنشور. يدعم Render اتصالات WebSocket الواردة لخدمات الويب، ويوصي باستخدام `wss` على الإنترنت العام وبإبقاء العميل قادراً على إعادة الاتصال عند انقطاع الجلسة [1].

## بدائل السحابة

| الخيار | متى يناسب اللعبة | ملاحظة تشغيلية |
|---|---|---|
| **Koyeb Free Instance** | تجربة أولية أو مشروع هواية صغير | يوفر 512MB RAM و0.1 vCPU مجاناً، لكنه ينام بعد ساعة بلا حركة ولا يُوصى به للإنتاج [2]. |
| **Railway Free** | تجربة قصيرة مع نشر سريع من GitHub | يقدم رصيد استخدام شهرياً قدره 1 دولار؛ لذلك ليس خادماً مجانياً دائماً إذا زادت ساعات التشغيل [3]. |
| **Render Web Service** | الخيار الأبسط لخادم Node.js طويل الاتصال | اختر خطة تعمل باستمرار للمباريات الفعلية، واجعل الخدمة بمثيل واحد لأن الغرف حالياً في الذاكرة. |

> لا تستخدم حصة مجانية تنام تلقائياً كمضيف لمباراة مهمة؛ إيقاف المثيل يفصل اللاعبين ويمسح الغرف الحالية المحفوظة في الذاكرة.

## اختبار محلي بين جهازين على شبكة Wi‑Fi

نفّذ الخطوات من جهاز الكمبيوتر الذي يحتوي على المشروع. استبدل `192.168.1.50` بعنوان IPv4 المحلي للكمبيوتر؛ يمكن إيجاده في Windows عبر `ipconfig` أو في macOS/Linux عبر `ifconfig` أو `ip addr`.

1. صِل الكمبيوتر والهاتفين بالشبكة نفسها، وأوقف VPN على الأجهزة الثلاثة.
2. افتح نافذة طرفية أولى داخل مجلد المشروع وشغّل خادم الغرف:

   ```bash
   pnpm server:multiplayer
   ```

3. افتح نافذة طرفية ثانية. في Windows PowerShell نفّذ:

   ```powershell
   $env:EXPO_PUBLIC_MP_SERVER_URL='ws://192.168.1.50:3001/multiplayer'
   npx expo start --web --host lan --port 8081
   ```

   وفي macOS أو Linux:

   ```bash
   EXPO_PUBLIC_MP_SERVER_URL=ws://192.168.1.50:3001/multiplayer npx expo start --web --host lan --port 8081
   ```

4. تأكد من أن عنوان الصحة يفتح من الهاتف: `http://192.168.1.50:3001/health`. إذا فشل، اسمح لمنفذي TCP `3001` و`8081` داخل جدار الحماية في وضع **Private network**.
5. افتح من الهاتفين المتصفحين العنوان `http://192.168.1.50:8081`.
6. من الهاتف الأول أدخل الاسم وأنشئ غرفة. من الهاتف الثاني افتح **الغرف المتاحة الآن** واضغط **تحديث** ثم **انضم** على الغرفة الظاهرة، أو أدخل الرمز يدوياً.
7. بعد انضمام الضيف، انتقل بالطرفين إلى إعداد الجولات ثم ترتيب الكروت. في اختبار الويب المحلي استخدم `ws://` فقط لأن الاتصال كله داخل الشبكة المنزلية؛ عند النشر العام استخدم `wss://`.
