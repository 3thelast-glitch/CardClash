# تشغيل خادم Card Clash Multiplayer

يعمل خادم اللعب الجماعي عبر HTTP وWebSocket على المسار `/multiplayer`. يحتاج العميل إلى متغير البيئة `EXPO_PUBLIC_MP_SERVER_URL`، مثل:

```bash
EXPO_PUBLIC_MP_SERVER_URL=wss://your-service.example.com/multiplayer
```

## التشغيل المحلي

```bash
pnpm install
MULTIPLAYER_PORT=3001 pnpm server:multiplayer
```

يمكن فحص الصحة عبر `http://localhost:3001/health`، بينما يتصل العميل عبر `ws://localhost:3001/multiplayer`.

## Railway أو Render

يوجد ملفا `railway.toml` و`render.yaml` جاهزان لاستيراد المستودع. أنشئ خدمة Node من المستودع، ثم عيّن `EXPO_PUBLIC_MP_SERVER_URL` في بيئة تطبيق Expo إلى عنوان HTTPS/WSS للخدمة. لا تُضمّن أسراراً داخل التطبيق المحمول.

الخادم الحالي يحفظ الغرف والنتائج في ذاكرة العملية. لذلك يجب تشغيله كنسخة واحدة؛ تشغيل عدة نسخ خلف موازن تحميل دون مخزن حالة مشترك قد يوزع لاعبي الغرفة الواحدة على عمليات مختلفة. إذا كان النشر على Manus WebDev، فالنمط المحجوز Reserved Hosting أنسب من Autoscale لهذه الحالة ذات الحالة داخل الذاكرة.

## بروتوكول الأدوار

تبدأ الجولة بالمضيف، وتُرسل قيمة `turnPlayerId` مع `BATTLE_START`. بعد كشف اللاعب الأول تُرسل `TURN_CHANGED` وينتقل الدور للاعب الآخر. بعد اكتمال النتيجة يتناوب اللاعب الذي يبدأ الجولة التالية. الخادم يرفض أي `REVEAL_CARD` خارج الدور أو خارج رقم الجولة الحالي.

## ملاحظات الإنتاج

يجب إضافة مخزن حالة مشترك، مثل Redis، قبل تشغيل عدة نسخ من الخادم. كما يوصى بتفعيل TLS، وتحديد حد أقصى لحجم الرسالة، وإضافة مصادقة جلسة قصيرة العمر قبل فتح الخدمة للعامة.
